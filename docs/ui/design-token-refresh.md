## v2 추가 — 실제 화면 기반 리서치 (2026-08-21)

1차 리서치(fork 3개)는 Chrome 브라우저 확장 연결 실패로 텍스트 2차 자료에 의존했음. 확장 연결 복구 후 실제 화면을 방문해 아래를 확인:

- **Mobbin**: 실제 화면 브라우징은 회원가입(계정 생성) 필요 — 계정 생성은 에이전트가 대신 할 수 없는 항목이라 마케팅 페이지만 확인, 실화면 검증 불가(유지되는 제약).
- **WWIT** (`wwit.design`): 로그인 없이 실제 한국 앱 스크린샷 확인 가능. 금융 카테고리에서 **네이버페이**(자산 화면), **삼쩜삼**(세금 환급, 홈 대시보드) 실물 확인.
- **Behance**: `senior healthcare app design` 검색으로 **"툭, 안부 | Family Health Check-in & Care App"** 프로젝트 발견 — ONDAM의 Senior+Guardian 이원 구조와 개념이 거의 동일(자녀가 부모 건강을 챙기는 앱). IA, 실제 화면 색상/컴포넌트까지 상세 확인.
- **Dribbble**: `elderly-care-app`/`health-dashboard` 검색 결과가 시니어 케어와 무관한 콘텐츠(광고, 일반 대시보드) 위주라 신뢰도 낮음 — 일반 대시보드 카드 패턴(도넛 게이지 차트, 스파크라인 미니카드) 정도만 참고.

### 실물 확인 — 네이버페이 "자산" 화면 (WWIT)

- 배경: 흰색. 상단 배너: 초록 계열 CTA 버튼("포인트 받기")
- "총 자산" 섹션: 큰 숫자 + 퍼센트 변화율
- **퀵액션 아이콘 행**: 5개 원형 아이콘, 각기 다른 파스텔 배경색(퍼플/블루/옐로/퍼플/블루 계열) 위에 흰 아이콘
- **리스트 행**: 원형 브랜드 로고 아이콘 + 좌측 라벨 + 우측 금액, 얇은 구분선
- → ONDAM Guardian 요약 카드에 적용 가능: 색상을 다르게 준 원형 아이콘 배지로 카테고리 구분, 금액/수치는 우측 정렬

### 실물 확인 — 삼쩜삼 홈 대시보드 (WWIT)

- 스플래시: 다크 네이비 배경 + 일러스트
- 홈 화면: 흰 배경, 파란색 강조 텍스트로 핵심 금액 표시, **단계형 프로그레스 바**(신청완료→반환중→입금완료→신청완료), 하단 리스트형 퀵링크(chevron 포함)
- → Guardian 대시보드의 "진행 상태" 표현(예: 분석 진행률)에 단계형 프로그레스 바 패턴 참고 가능

### 실물 확인 — "툭, 안부" (Behance, 가장 근접한 레퍼런스)

**컨셉**: "가볍게 챙기는 부모님 건강" — 자녀가 부모 건강을 확인하고 챙기는 앱. ONDAM Guardian이 Senior를 모니터링하는 구조와 정확히 대응.

**정보구조(IA)**: 부모(Senior)/자녀(Guardian) 역할별로 홈·안부·건강노트·에너지샵 메뉴를 동일한 이름으로 나란히 설계하되 내용은 역할에 맞게 분리 — ONDAM의 Senior/Guardian 앱 분리 구조와 동일한 설계 원리. "부모는 간단히 기록, 자녀는 한눈에 확인·반응"이라는 역할 구분 문장은 `ui-principles.md`의 Guardian 원칙 1("빠른 상황 파악")과 정확히 일치.

**색상 (육안 관찰, 정확한 hex 아님 — 실측 필요)**:
- 배경: 민트/세이지 그린 계열(연한 청록빛 초록) ↔ 크림/오프화이트 계열이 화면 목적에 따라 교차 사용
- 카드: 흰 배경, 둥근 모서리(약 16~20px 추정)
- 아이콘 배지: 파스텔 톤 원형(연한 블루=수분, 연한 핑크/레드=투약, 연한 그린=운동) — 카테고리별 색상 구분
- 프로그레스 바: 오렌지 계열(수분 등 미달성)·그린 계열(달성) — 값의 상태(부족/충분)를 색으로 구분하는 패턴
- CTA 버튼: 그린/민트 계열 단색, 둥근 pill 형태
- 태그/라벨("부모님 홈 화면", "자녀 화면" 등 안내 라벨): 코랄/오렌지 계열

**컴포넌트 패턴**:
- 건강 지표 카드 리스트: `아이콘 배지 + 제목 + 보조설명 1줄 + 큰 숫자(단위 포함) + 진행바` — ONDAM `AppStatCard`/`AppFeeStatisticsSection`에 그대로 대응 가능한 구조
- 채팅형 "안부" 인터페이스: 부모-자녀 간 대화형 UI, 사진 첨부 가능, 하단에 주제별 quick-reply 칩(수분/식사/복용/운동/기분/일정) — 선택된 칩만 색상 채움
- 하단 네비게이션: 5탭(홈/건강노트/안부/에너지샵/마이페이지), 아이콘+라벨
- "시니어를 위한 글자 크기 선택" 기능이 온보딩/설정에 명시적으로 노출됨 — Easy Mode 진입점을 설정 안에 숨기지 않고 눈에 띄게 노출하는 것이 실제 유사 서비스에서도 채택된 패턴, `ui-principles.md` Easy Mode 원칙 8("앱 전체의 핵심 UX")과 부합

**ONDAM 적용 판단**:
- 색상 방향(민트/세이지 그린 + 크림 배경 + 오렌지·코랄 accent)은 v1에서 제안했던 "신뢰(블루/에메랄드) + 따뜻함(파스텔) 공존" 방향과 궤를 같이하되, **그린이 아니라 민트/세이지 톤을 기본 배경 계열로, 오렌지/코랄을 accent로 쓰는 조합이 시니어 대상 앱에서 실제로 사용되고 있음**을 확인 — v1의 "따뜻함 accent" 후보를 코랄/오렌지 계열로 구체화하는 근거로 채택 가능
- 카테고리별 파스텔 아이콘 배지 + 진행바 조합은 ONDAM Guardian 통계/Senior 건강 관련 화면(있다면) 모두에 재사용 가능한 컴포넌트 패턴으로 추천
- 정확한 hex 값은 육안 관찰이라 신뢰도가 낮음 — 코드 반영 전 스크린샷을 이미지 편집 도구로 열어 실측하거나, 유사 톤을 KRDS 명도단계 방식(v1 원칙 3)에 맞춰 새로 산출하는 것을 권장

## 리서치 방법 및 제약 (중요)

3-fork 병렬 리서치를 실행했으나, **세 fork 모두 Chrome 브라우저 자동화 확장이 연결되지 않아** 계획했던 실사이트 스크린샷 기반 조사를 하지 못했다:

- **Mobbin**: Cloudflare 403으로 완전 차단 (WebFetch 대체 시도도 실패)
- **Behance / Dribbble**: JS 렌더링 콘텐츠라 WebFetch로는 메타데이터(제목·디자이너명)만 확보, 실제 색상/레이아웃 확인 불가
- **Page Flows**: 화면 녹화가 구독 전용이라 개요만 확인
- **Awwwards**: 실제 수상작이 아닌 일반 UX 아티클만 검색됨
- **WWIT**: WebFetch로 정상 접근, 카테고리·소개 앱 목록 확보
- **Apple HIG / Material 3 / KRDS / WCAG**: 텍스트 기반 desk research로 정상 진행 (Fork 3 전체)

**결론적으로 이 문서의 "UX 흐름/원칙" 관련 결론(Fork 1, Fork 3)은 신뢰도가 높고, "정확한 색상 hex/타이포 px 값"(Fork 2 일부)은 실제 화면이 아닌 2차 텍스트 자료 기반이라 **방향성 근거로만 쓰고 최종 값 채택 전 실물 검증이 필요**하다. 브라우저 확장 연결을 복구해 재조사하거나, 사용자가 이 v1 방향에 동의하면 바로 코드 반영 후 실제 화면에서 육안 검증하는 절충도 가능(아래 "다음 단계" 참고).

## 종합 원칙 (3개 fork 교차 확인)

1. **UX 흐름/정보계층은 변경 불필요** — 기존 `ui-principles.md`의 원칙(Guardian: 위험도순 정렬, 점진적 노출 / Senior: 정보 밀도 최소화, 한 화면 한 목적)이 실제 업계 관행(WWIT 금융앱, 일반 대시보드 패턴)과 부합함을 재확인.
2. **터치 영역·기본 대비 기준은 변경 불필요** — 일반 48dp/Easy Mode 56~76dp가 HIG(44pt)·Material(48dp)를 이미 상회. WCAG AA(4.5:1/3:1)도 현재 원칙에 반영되어 있음.
3. **컬러 토큰 구조 전환 권장 (핵심 변경)** — 현재 `AppColors`는 `primary`/`textPrimary` 등 평면 나열이라 "이 배경엔 이 텍스트색"이 코드로 강제되지 않음. Material 3의 **on-색 페어**(`onPrimary`/`onSurface`/`onError`)와 KRDS의 **명도단계→보장대비**("명도 40=3:1, 50=4.5:1, 70=7:1") 방식을 도입하면 대비 사고를 구조적으로 방지할 수 있음.
4. **Easy Mode는 AA(4.5:1) → AAA(7:1) 상향 검토** — 고령층 사용성 연구(arXiv 2504.12690)에서 참가자들이 "흑백에 가까운 고대비"를 선호. Normal Mode는 AA 유지, Easy Mode만 AAA로 올리는 절충안.
5. **컬러 톤 방향** — "신뢰"(네이비/블루+에메랄드)와 "따뜻함"(파스텔 코랄/피치) 두 방향이 리서치에서 공존. ONDAM은 이미 `primary`(블루)+`secondary`(에메랄드 계열)로 "신뢰" 축을 갖고 있으므로 이를 유지하고, Senior Easy Mode에 "따뜻함" accent를 별도로 얹는 절충 — 단, 기존 긴급/위험 색(코랄 계열 `#FF6B78`)과 채도·색상군이 겹치지 않게 분리해야 함(`ui-principles.md` 원칙 6, 색상 단독 의존 금지와도 연결).
6. **타이포 — Easy Mode 본문 강화** — Easy Mode 본문은 20pt 이상 + font-weight 700 이상 권장 근거 확보. 카드/버튼 테두리도 Easy Mode에서 더 두껍고 진하게(오타치 방지 + 저시력 대응).
7. **차트 컬러 절제** — Guardian 통계 차트는 시맨틱 3색(양호=그린/주의=옐로/위험=레드)으로 고정, 다색 파이차트 지양 — 기존 원칙 재확인, 변경 없음.

- **변경 불필요**: 현재 `AppSpacing`/`AppRadius` 스케일에 대해 이번 리서치는 반박 근거를 찾지 못함(KRDS radius 체계와 단계 수 유사).
