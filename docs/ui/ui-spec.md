# UI 명세

> 기존 온담앱(https://ondam-web.pages.dev/, /guardian)의 실제 렌더링 결과(스크린샷 + `getComputedStyle` 측정)를 참고하되 그대로 복제하지 않고, `.claude/rules/ui-design.md`의 토큰 체계(`AppColors`/`AppTextStyles`/`AppSpacing`/`AppRadius`)로 재해석한다. Phase 1(v4) 이후 이 토큰들의 실제 위치는 `lib/app/theme/`가 아니라 **`packages/design_system/lib/src/tokens/`**(Senior/Guardian 두 앱이 공유하는 패키지)다.
>
> **개정 이력**: `docs/architecture/technical-decisions.md` v2에서 UI 결정 5개(쉬운 모드 범위, 긴급 버튼 색상 토큰 구조, `AppEmptyState` 공통화, Loading 상황별 병행, 보호자 연결 전 Mock 프리뷰 제거)가 확정되어 관련 절을 갱신했다. v3에서는 신규 요구사항(음성 비서/쉬운 모드 Main 강화/카메라 플래시/답변 신뢰도/보호자 고지서 통계)의 UI 방향을 "신규 요구사항 UI 반영" 절에 추가했다.
>
> ⚠️ 보호자 홈/받은연락/통계 화면 스크린샷은 기존 앱의 "연결 전 화면 미리보기(Mock 데이터)" 상태에서도 캡처되었으나, **이 Mock 프리뷰 자체는 확정 결정으로 신규 앱 프로덕션에서 사용하지 않는다.** 레이아웃/컴포넌트 참고 자료로만 활용하고, 연결 전 상태는 `AppEmptyState`로 대체한다(§"Empty State" 참고).

## 참고한 기존 화면

| 화면 | 캡처 출처 | 참고한 요소 |
|---|---|---|
| 어르신 홈(일반/쉬운 모드) | 직접 조작 스크린샷 | 카드 레이아웃, 대형 버튼 UI, 색상 대비 |
| 로그인/온보딩 | 직접 조작 스크린샷 | 폼 필드, 소셜 로그인 버튼, 단계형 진행 |
| 긴급 도움 모달 | 직접 조작 스크린샷 | 위험/경고 색상, 원형 플로팅 버튼 |
| 보호자 홈/받은연락/통계 | 직접 조작 스크린샷 | 상태 배지, 통계 카드, 막대그래프 |
| 각종 Empty State | 직접 조작 스크린샷 | 빈 상태 문구 톤 |
| 실측 CSS 값(`getComputedStyle`) | 브라우저 JS 실행 결과 | 실제 색상 RGB, 폰트 크기/굵기, radius |

## UI 분석

### Layout

- 모바일 세로 1열 카드 스택 레이아웃. 헤더(타이틀/뒤로가기) + 콘텐츠(스크롤 가능) + 하단 고정 네비게이션(4개 탭) 구조가 어르신 앱/보호자 앱 공통.
- 홈 화면은 "카드 리스트 + 카드 하단의 보조 링크(사용 방법 보기)" 패턴을 반복 사용.
- 긴급 도움은 플로팅 버튼(우측 하단 상시 노출) → 모달 형태로 확장.

### Color

실측한 RGB 값과 코드베이스에 이미 존재하는 placeholder 토큰(`app_colors.dart`)을 비교한 결과, 우연히도 매우 근접하다. 매핑은 아래 "토큰 매핑" 절 참고.

- Primary(파랑, 주요 버튼/포커스/링크): 실측 `rgb(61,107,245)` ≈ `#3D6BF5`
- Danger/긴급(빨강): 실측 `rgb(255,107,120)` ≈ `#FF6B78` (도움 버튼), 위험 카드 배경은 더 옅은 붉은 톤(`#FFE5E7` 계열 추정)
- 위치/경로당 아이콘: 초록 계열
- 정보 아이콘: 파랑 계열(Primary와 통일)
- 배경(페이지 전체): 실측 `rgb(245,247,251)` ≈ `#F5F7FB` (연한 블루그레이, 순백색 아님)
- 본문 텍스트: 실측 `rgb(23,27,43)` ≈ `#171B2B` (완전한 검정이 아닌 네이비블랙)
- 보조 텍스트: 실측 `rgb(100,109,124)` ≈ `#646D7C`
- 소셜 로그인 버튼: 구글(흰 배경+테두리), 네이버(초록 `#03C75A` 계열), 카카오(노랑 `#FEE500` 계열) — 각 브랜드 컬러 그대로 사용

### Typography

- 폰트 스택: 시스템 폰트 우선(`-apple-system, BlinkMacSystemFont`) + 한글 폴백(`Malgun Gothic`, `Apple SD Gothic Neo`). 별도 웹폰트 로드 없음 — Flutter에서도 시스템 기본 폰트(또는 프로젝트 지정 폰트)로 충분.
- 헤딩(예: "무엇을 도와드릴까요?"): 34.5px / weight 800 → `AppTextStyles.displayLarge`(32/bold)에 가장 근접. 기존 값이 근소하게 더 크고 굵어 근사.
- 본문/설명 텍스트: 16.675px → `AppTextStyles.bodyLarge`(16/normal)에 근접. 단, 관찰된 실제 폰트는 다소 굵어 보이는 경우가 많아 weight는 화면별로 확인 필요.
- 카드 타이틀(예: "문서 촬영"): 시각적으로 titleMedium~headlineMedium 사이 — 화면별 재현 시 `AppTextStyles.titleMedium`부터 시작해 조정 권장.
- 쉬운 모드에서는 전반적으로 폰트 크기가 확연히 커짐(버튼 라벨이 두 줄로 감싸질 정도) — 별도 스타일 세트라기보다 기존 스타일에 스케일 배수를 적용한 것으로 추정.

### Spacing

- 카드 간 간격, 카드 내부 패딩 모두 넉넉한 편(터치 영역과 가독성을 고려한 여유 있는 spacing). 기존 프로젝트의 `AppSpacing` 스케일(4/8/16/24/32/48)로 근사 가능:
  - 카드 내부 패딩: `AppSpacing.md`(16)~`AppSpacing.lg`(24) 근사
  - 섹션 간 간격: `AppSpacing.xl`(32) 근사
  - 리스트 아이템 간 간격: `AppSpacing.sm`(8)~`AppSpacing.md`(16)

### Button

- Primary 버튼: pill 형태(`border-radius: 999px`) → `AppRadius.full`과 정확히 일치. 큰 터치 영역, 굵은 폰트.
- 카드형 버튼(문서 촬영 등): 사각형에 둥근 모서리, 흰 배경 + 얇은 테두리 또는 미세한 그림자.
- 쉬운 모드 버튼: 정사각형에 가까운 큰 카드, 아이콘(원형 흰 배경 안에 아이콘) + 텍스트 두 줄 배치.
- 위험/긴급 버튼(119/112): 채워진 빨강 배경 + 흰 텍스트로 시각적 위계를 명확히 분리.

### Card

- 흰 배경 카드가 기본. 리스트형 카드(정보/경로당/통계)는 좌측에 아이콘(원형 컬러 배경), 우측에 화살표(`>`) 또는 액션 버튼(전화 아이콘 등).
- "받은 연락" 카드에는 좌측 상단에 "새 연락" 배지(파란 필)가 추가로 붙는 패턴.

### Navigation

- 하단 고정 탭바 4개(어르신: 정보/홈/기록/더보기, 보호자: 홈/받은연락/기록/통계/더보기 — 보호자는 5개... 실측은 4탭+더보기로 보임, 화면별 재확인 필요).
- 활성 탭은 Primary 색상으로 아이콘+라벨 강조, 비활성은 회색.
- 배지 카운트(빨간 원 안 숫자)로 안읽음 알림 표시(보호자 앱 "받은 연락" 탭).
- 상세 화면은 상단에 "← 홈으로/← 뒤로" 텍스트 링크로 복귀(별도 back arrow 아이콘 버튼이 아닌 텍스트+화살표 조합).

### Icon

- 라인 스타일보다 채워진(filled) 원형 배경 위에 흰색 아이콘을 얹는 패턴이 일관적으로 사용됨(카메라/말풍선/핀/사람 등). 기능별 배경색으로 카테고리를 구분(파랑=문서/문자, 초록=위치, 빨강=위험/긴급).

### 상태별 UI

- **로딩(확정)**: "내 위치를 확인하고 있어요..." 같은 텍스트 기반 로딩 상태가 관찰됨. `technical-decisions.md` UI 결정 D에 따라 신규 앱에서는 **상황별로 병행 표시**한다 — 단순 데이터 로딩은 Progress Indicator만, 중요 작업(문서 분석, 결제성 정보 등)은 "지금 무슨 일이 일어나고 있는지" 설명 텍스트 + Progress Indicator를 함께 표시. `AppLoading` 위젯이 두 variant를 지원하도록 설계.
- **에러**: "주변 시설 정보를 불러오지 못했어요. 잠시 후 다시 시도해주세요." + 재시도 버튼("다시 찾기") 조합. `AppError` 위젯 패턴에 부합.
- **빈 상태(Empty, 확정)**: 아이콘 없이 회색 톤의 안내 문구 두 줄(무엇이 없는지 + 어떻게 채울 수 있는지)로 구성. 예: "아직 분석한 기록이 없습니다. 문서 찍기나 문자 보기를 이용해보세요." `technical-decisions.md` UI 결정 C에 따라 이 톤을 **공통 `AppEmptyState` 컴포넌트**로 구현하고, 화면마다 개별 제작하지 않는다. 문구/아이콘/Action(버튼)만 화면별로 주입.
  - 보호자 앱 "연결 전" 상태도 이 컴포넌트로 구현: "아직 연결된 어르신이 없습니다 → 어르신 연결하기"(Action 버튼).
- **위험/경고**: 빨간 텍스트 + 느낌표 아이콘 + 옅은 빨강 배경 카드로 표현, 색상에만 의존하지 않고 "위험 감지" 텍스트 배지를 병행(접근성 원칙에 부합).

### Empty State

위 "상태별 UI" 참고. 3곳(분석 기록/일정/고지서 통계/받은 연락)에서 일관된 톤 확인. **확정**: 공통 `AppEmptyState` 컴포넌트 하나로 구현(문구/아이콘/Action 주입형). 보호자 앱의 Mock 데이터 프리뷰(연결 전 화면)는 이 컴포넌트의 "연결하기" Action이 있는 variant로 대체하고, Mock 데이터 자체는 프로덕션에서 제거한다.

### Error State

위치 조회 실패 케이스 1건 확인. 그 외 네트워크 에러 등은 이번 세션에서 재현하지 못해 확인 필요.

### Responsive

- 브라우저 창 크기 조절에 따라 요소 위치가 유동적으로 재배치되는 반응형 레이아웃 확인(자동화 중 뷰포트 크기가 매 스크린샷마다 미세하게 달라지는 현상 자체가 반응형 동작의 방증). Flutter 재구현 시 고정 픽셀 대신 `MediaQuery`/`Flexible` 기반 설계가 기존 UX와 부합.

### Accessibility

- 글자 크기 3단계(보통/크게/아주 크게), 음성 안내(TTS) on/off, 음성 읽기 속도 4단계(0.5~2배속) 등 접근성 설정이 매우 풍부함 — 고령층 타깃 앱의 핵심 요구사항으로 신규 앱에도 필수 반영.
- 위험 상태를 색상(빨강)뿐 아니라 아이콘(느낌표)과 텍스트 배지("위험 감지")로 병행 전달 — WCAG 원칙에 부합하는 기존 설계를 유지할 가치가 있음.
- 쉬운 모드는 그 자체로 하나의 접근성 기능이며, **확정**: 단순 확대가 아니라 버튼크기/정보량/Navigation/화면복잡도/텍스트/여백/기능우선순위까지 바뀌는 별도 UX 모드로, 전체 앱(하단 Navigation 포함)에 적용하고 글자 크기 설정과는 독립적으로 동작하며 앱 재실행 후에도 유지한다(`technical-decisions.md` UI 결정 A, `implementation-plan.md` §2 상세 설계 참고).

## 신규 요구사항 UI 반영 (v3)

> 신규 요구사항(음성 비서/쉬운 모드 Main 강화/카메라 플래시/답변 신뢰도/보호자 고지서 통계)의 UI 방향만 정의한다. 실제 컴포넌트 구현, STT/TTS 연동, confidence 계산은 하지 않는다. 관련 기술 미결정 사항은 `technical-decisions.md` OPEN QUESTIONS 9~12 참고.

### 쉬운 모드 Main UX

- 쉬운 모드는 설정 화면 안의 옵션이 아니라 **홈 화면 자체의 기본 경험**으로 설계한다. 큰 버튼, 핵심 기능 중심 Navigation(문서/문자/경로당/음성비서/긴급도움), 직관적 안내 문구가 한 화면 안에서 자연스럽게 이어지도록 구성.
- 홈에서 가장 자주 쓰는 기능까지 **최소 탭 수(1~2회)**로 도달하는 것을 설계 기준으로 삼는다 — 새 카드/버튼을 추가할 때마다 "이게 정말 최상위에 있어야 하는가"를 기준으로 우선순위를 재검토.
- 음성 비서 진입점과 긴급 도움 버튼은 쉬운 모드 홈에서 동등하게 눈에 띄는 위치(예: 화면 하단 고정 영역)에 배치하는 것을 우선 검토.

### 음성 비서 상태

| 상태 | UI 방향 |
|---|---|
| **진입 버튼** | 홈(특히 쉬운 모드)에 상시 노출되는 큰 마이크 아이콘 버튼. 긴급 도움 버튼과 시각적으로 구분되는 색상(Primary 계열 권장, 긴급 버튼의 `emergency` 톤과 혼동되지 않게) |
| **음성 입력 중** | 마이크가 활성화되어 듣고 있음을 시각적으로 표현(예: 파형 애니메이션, 버튼 강조) + "듣고 있어요" 류 텍스트 병행(청각 정보에만 의존하지 않음) |
| **처리 중(STT→의도분석→AI)** | `AppLoading`의 "중요 작업" variant 재사용 — "요청하신 내용을 확인하고 있어요" 같은 진행 상태 텍스트 + Progress Indicator |
| **답변(음성 출력)** | 화면에 답변 텍스트를 함께 표시(음성만으로 끝내지 않음 — 청각 장애/소음 환경 고려), TTS 재생 중임을 나타내는 인디케이터, "다시 듣기" 액션 제공 검토 |
| **인식 실패/무음** | 에러로 처리하지 말고 "다시 한번 말씀해주세요" 같은 부드러운 재시도 유도 문구 사용(어르신 대상 톤 유지) |

### 카메라 플래시 상태

- 촬영 화면에서 플래시 상태(OFF/ON/자동)를 **항상 텍스트 또는 명확한 아이콘 라벨과 함께** 표시(아이콘만으로 상태를 유추하게 하지 않음).
- 일반 모드: 촬영 화면 상단 또는 하단에 상태 표시 + 탭하여 전환 가능한 컨트롤.
- 쉬운 모드: 작은 아이콘 토글이 아니라 **큰 버튼**으로 제공, 현재 선택된 상태가 배경색/테두리로 뚜렷이 구분되게.
- 촬영 버튼을 누르기 전에 현재 플래시 상태를 반드시 확인할 수 있어야 한다(촬영 직후에야 알게 되는 구조 금지).

### 답변 신뢰도 표시

- **숫자나 퍼센트, 복잡한 그래프로 표현하지 않는다** (특히 어르신용 UI에서는 절대 금지 원칙).
- 3단계 이상의 세분화된 표현 대신, 사용자에게는 아래와 같은 **문장형 표현**을 기본으로 한다(정확한 문구 확정은 OPEN QUESTIONS 11):

```text
높음 → "이 답변은 비교적 확실해요."
보통 → "조금 더 확인이 필요해요."
낮음 → "정확하지 않을 수 있어요."
```

- 색상은 보조 신호로만 사용(예: 높음=Primary/차분한 색, 낮음=주의를 끄는 색이되 위험 문자 경고와는 구분되는 톤 — 신뢰도 낮음이 "위험"을 의미하는 것은 아니므로 긴급/위험 색상과 혼동되지 않게 별도 톤 사용을 검토).
- 아이콘 + 텍스트를 병행해 색상에만 의존하지 않는다(기존 위험 표시 원칙과 동일).
- 표시 위치: 분석 결과 상단(원문/요약보다 먼저 보이는 위치)에 배치해, 사용자가 내용을 읽기 전에 "이 답변이 얼마나 확실한지"부터 인지하게 한다.
- 이 표시는 의료/법률/금융 등 고위험 판단을 의미하지 않으며, **온담 AI 분석 결과 자체의 불확실성**만을 안내한다는 원칙을 문구에도 반영(과장되게 "위험할 수 있음"처럼 읽히지 않도록 주의).

### 보호자 고지서 통계 UI (v10: 부분 구현 — ui-screen-spec.md "통계" 참고)

- 원본 문서(사진)를 그대로 보여주지 않고, 구조화된 데이터(금액/기한/항목 등)를 카드·간단한 그래프 형태로 표시(기존 "안심 통계" 화면의 카드+막대그래프 패턴 재사용).
- 최종 통계 항목은 **여전히 미확정(OPEN QUESTIONS 12)** — Phase 6에서도 확정하지 않았다. 그래서 실제 구현은 "카드 그리드 + 기간별 추이 그래프" 대신, 스키마와 무관한 집계(이번 달 분석 건수/위험 문자 건수, `AppStatCard` 2개 + 추세 문장)만 카드로 보여주고, 고지서 구조화 필드는 기록별 원본을 그대로 나열하는 데 그쳤다. "카드 그리드 + 기간별 추이 그래프" 레이아웃은 OPEN QUESTIONS 12가 해소된 뒤 다시 시도한다.
- 이상 변화(예: 전월 대비 금액 급증) 강조 카드는 통계 항목 자체가 미확정이라 구현하지 않았다 — 항목이 정해지면 함께 설계한다.

## 유지 vs 개선 요소

### 유지(KEEP)할 요소

- 원형 컬러 배경 + 흰 아이콘 조합의 일관된 아이콘 시스템
- pill 버튼 + 카드형 버튼의 위계 구분
- 위험 상태의 색상+아이콘+텍스트 3중 표현
- Empty/Error State의 "무엇이 없는지 + 다음에 뭘 하면 되는지"를 함께 안내하는 문구 패턴
- 쉬운 모드의 대형 버튼 UI 자체(단, 실제 구현은 새로 설계)

### 개선할 요소

- 하드코딩된 것으로 보이는 색상 값들을 `AppColors` 토큰으로 전면 재정의(기존 placeholder 값이 실측값과 매우 근접해 그대로 기준점으로 활용 가능 — 아래 토큰 매핑 참고).
- **(확정)** 로딩 상태가 텍스트로만 표현되는 화면(위치 조회 등)에 시각적 로딩 인디케이터(`AppLoading`)를 상황별로 병행 표시(위 "상태별 UI - 로딩" 참고).
- 배경색이 페이지마다 미묘하게 다르게 보이는 경우가 있어(순백 vs 연한 블루그레이) 신규 앱에서는 `AppColors.background`/`AppColors.surface`를 명확히 구분해 일관되게 적용.
- **(확정)** 보호자 앱의 Mock 데이터 기반 "연결 전 화면 미리보기"는 프로덕션 UI에서 제거하고 `AppEmptyState`로 대체.

## 토큰 매핑

기존 관찰값 → 가장 가까운 `packages/design_system/lib/src/tokens/` 토큰. 코드베이스에 이미 존재하는 placeholder 값이 실측값과 우연히 근접해, 별도 신규 색상 추가 없이 기존 placeholder를 그대로 채택 가능한 경우가 많다.

| 기존 관찰값 | 가장 가까운 토큰 | 비고 |
|---|---|---|
| Primary blue `rgb(61,107,245)` (`#3D6BF5`) | `AppColors.primary` (`#3D5AFE`) | 매우 근접 — 기존 placeholder 그대로 사용 가능 |
| 배경 `rgb(245,247,251)` (`#F5F7FB`) | `AppColors.surface` (`#F5F5F7`) | 근접 — `surface`로 매핑, 순백 영역은 `AppColors.background`(`#FFFFFF`) |
| 본문 텍스트 `rgb(23,27,43)` (`#171B2B`) | `AppColors.textPrimary` (`#1A1A1A`) | 근접(더 네이비에 가까움) — 필요 시 미세 조정 검토 |
| 보조 텍스트 `rgb(100,109,124)` (`#646D7C`) | `AppColors.textSecondary` (`#6E6E73`) | 근접 |
| 긴급/위험 빨강 `rgb(255,107,120)` (`#FF6B78`) | `AppColors.error` (`#D32F2F`) | **다름 — 기존 error 토큰이 더 어둡고 채도 높은 빨강.** 온담의 긴급 버튼은 더 밝고 채도 낮은 코랄 톤. **확정(`technical-decisions.md` UI 결정 B)**: `AppColors.error`를 무조건 재사용하지 않고, 필요 시 별도 `AppColors.emergency` 토큰을 신설할 수 있는 구조로 간다 — 정확한 HEX 값은 접근성 대비 검토 후 확정(OPEN QUESTIONS).
| pill 버튼 radius `999px` | `AppRadius.full` (`999`) | 정확히 일치 |
| 헤딩 34.5px/800 | `AppTextStyles.displayLarge` (32/bold) | 근사(온담이 근소하게 더 큼) |
| 본문 16.675px | `AppTextStyles.bodyLarge` (16) | 근사 |
| 카드 간/섹션 간 여백 | `AppSpacing.md`~`AppSpacing.xl` | 정확한 px 미측정 — 화면별 구현 시 시각적으로 맞춰 조정 |

> 참고: `AppColors.secondary`(`#00BFA5`, 청록)에 대응하는 요소는 이번 분석에서 명확히 발견하지 못했다. 경로당/위치 관련 초록 아이콘이 있었으나 정확한 색상값은 미측정 — 실제 구현 시 재측정 후 `secondary` 또는 별도 토큰 여부 결정.
