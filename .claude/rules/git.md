# git.md — Git 규칙

## Commit

- 하나의 커밋은 하나의 논리적 변경만 담는다 (기능 추가와 무관한 리팩터링을 같은 커밋에 섞지 않는다).
- 커밋 메시지는 "무엇을" 보다 "왜"를 설명한다.
- 사용자가 명시적으로 요청하기 전에는 커밋하지 않는다.

## Branch

- `main`(또는 `master`)은 항상 실행 가능한 상태를 유지한다.
- 기능 개발은 `feature/<name>`, 버그 수정은 `fix/<name>` 형태의 브랜치에서 진행한다.
- UI 리디자인 작업은 기능 브랜치와 분리해 `ui/<name>` 형태로 진행하는 것을 권장한다 — 기능 변경과 UI 변경 diff를 섞지 않기 위함.

## 민감정보 / .env

- `.env`는 절대 커밋하지 않는다 (`.gitignore`에 이미 등록됨).
- API Key, Secret, 비밀번호를 소스 코드나 커밋 메시지에 하드코딩하지 않는다.
- `.env.example`에는 값 없이 변수 이름만 작성한다.
- 커밋 전 `git status`/`git diff`로 의도치 않게 포함된 민감 파일이 없는지 확인한다.

## 변경사항 확인

- 커밋하기 전 `git status`와 `git diff`로 실제 변경 내용을 확인한다. `git add -A`/`git add .`처럼 전체를 무조건 스테이징하지 않고, 의도한 파일만 추가한다.
- 큰 변경(특히 UI 리디자인)은 커밋 전에 "UI 외의 코드가 변경되었는가?"를 다시 확인한다 (`ui-redesign` skill 참고).

## 불필요한 파일 금지

- 빌드 산출물(`build/`, `.dart_tool/` 등), IDE 설정, OS 임시 파일을 커밋하지 않는다 — `.gitignore`가 이미 대부분 커버한다.
- 사용하지 않는 asset, 임시 스크립트, 디버그용 파일을 커밋하지 않는다.
